Missingness type

A Pythagoras card

Nick Ward

🧭 Purpose

The Missingness type card asks whether missingness can be predicted from the other available predictors or from observation order. It uses cross-validated decision trees and permutation tests to distinguish detectable pattern from results that are weak, uncertain, or unsupported.

For the broader framework, see predictability and missing-data mechanisms in Background on missing values.

🎯 Goals

  1. Primary: Identify variables whose missingness has reproducible structure.
  2. Secondary: Reveal predictors and sequence effects that may explain that structure.
  3. Tertiary: Inform the choice between investigation, imputation, and cautious deletion.

🧠 How it works

For each sufficiently incomplete predictor, a decision tree classifies values as missing or observed using the other eligible predictors. A separate Obs-count model predicts how many values are missing in each observation. Cross-validation compares held-out performance with a matched null model, while label permutations estimate how surprising the improvement is under independence.

Classification uses balanced accuracy so that rare missing cases are not overwhelmed by the observed majority. The aggregate count model uses R-squared. A Patterned interpretation requires adequate sample counts, practical improvement, absolute performance, fold consistency, and the selected permutation evidence. Failure to meet all criteria may produce Random, Uncertain, or Insufficient data rather than proving a particular missing-data mechanism.

🏞️ Front

The front contains the Obs-count tab and dynamically managed tabs for eligible incomplete variables. Each tab shows a fitted decision tree that illustrates the strongest splits found in the analysis. Read the tree as an explanation of the fitted pattern, not as an independent validation result.

🔄 Flip side

The flip side summarizes each model’s interpretation and supporting evidence, including missing proportion, score, null score, improvement, fold consistency, and raw or adjusted permutation p-values. Sort and filter the table to identify the strongest and least reliable results.

🛠️ Controls and actions

This card has no data-changing action. Choosing tabs or changing diagnostic thresholds recalculates the assessment but leaves downstream data unchanged.

⚙️ Settings

The card’s Tour Guide gives a concise description of each setting.

🔎 Interpretation and next steps

Patterned means missingness is predictably associated with the supplied information; it does not distinguish missing at random from missing not at random in the formal causal sense. Random means the card did not find adequate predictive evidence under its current design, not that randomness has been proven. Uncertain and Insufficient data should prevent strong conclusions.

Use prominent tree splits as hypotheses. A split on row number can indicate drift in collection practices, but only when current row order has real meaning. Check the relevant observations and source process before choosing deletion or imputation.

⛔️ Limitations

  • Decision trees detect only patterns available in included predictors and optional row order.
  • Multiple-testing adjustment reduces false discoveries but does not eliminate them.
  • Sampling, rare missingness, and small folds reduce stability.
  • The tree shown on the front is explanatory; cross-validated metrics support the interpretation.
  • Observation weights are not currently used.

📌 Suggested workflow

  1. Ensure roles and observation ordering are meaningful.
  2. Review the aggregate missing-count result.
  3. Inspect variable tabs with Patterned or Uncertain interpretations.
  4. Compare tree splits with the metrics on the flip side.
  5. Test plausible explanations against the underlying data and collection process.

🔗 Data flow

  • Input: Upstream predictor values, missingness indicators, roles, and optional row order.
  • Output: The upstream data unchanged.
  • Data journey: This diagnostic card does not add a journey step.
