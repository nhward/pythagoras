Variable encoding

A Pythagoras card

Nick Ward

🧭 Purpose

Convert semantic Predictor variables into numeric features for downstream modeling. Place Variable encoding after assigning types, roles, level orders, and cyclic periods. The card previews six encoding families and can add their transformations to the sklearn pipeline while updating the outgoing data.

🎯 Goals

  1. Primary: Represent categorical, ordered, cyclic, and logical predictors numerically without losing their intended meaning.
  2. Secondary: Keep learned encodings inside the training pipeline.
  3. Tertiary: Make feature expansion and original-column removal visible through an encoding audit.

🧠 How it works

Each panel considers Predictor-role variables of its semantic type. Selecting an encoding applies it to all eligible variables in that panel. Generated columns receive the Predictor role, with names adjusted to avoid existing columns. Other variables pass through unchanged.

Table 1 - Encoding families
Panel Numeric representation
Nominal One-hot indicators: each indicates membership of a category. After optional rare-level pooling, two categories produce one indicator with a dropped reference; larger sets produce one per category. A constant produces no indicator.
Code Target means for numeric outcomes, or class probabilities for classification. Binary classification produces one feature for the second observed class; multiclass produces one per class. The default empirical Bayes method automatically smooths estimates toward the overall outcome.
Ordered By default, ranks 0 through d−1 for d declared levels. Optional polynomial contrasts produce up to d−1 columns describing linear, quadratic, and higher-order trends.
Cyclic Two features, sine and cosine of the position within the declared period. Numeric cycles use zero as their origin; categorical cycles use equally spaced positions beginning with the first declared level.
Basket One binary indicator per item learned during fitting. Repeated items count once; no reference item is dropped because several items can coexist. Unseen test items are ignored without adding columns.
Logical Integer 1 for True and 0 for False. Missing values remain missing.

Ordered and cyclic encodings preserve the upstream schema, including declared levels absent from the current observations. Numeric cyclic periods are explicit, never inferred from observed maxima.

Code encoding requires exactly one usable Target. Its training preview uses cross-fitting: each row’s encoding comes from other folds, excluding that row’s outcome. Future observations use mappings fitted to the training data and require no Target values. Unseen codes receive the training target mean or class proportions.

The exported pipeline contains unfitted recipes. Downstream training must fit those recipes within each training fold. The displayed data is a preview, not a substitute for fitting the pipeline during validation.

Basket vocabularies are learned separately for each source variable and training fold. Empty baskets and baskets containing only unseen items produce all zeros. A missing basket produces missing values in every generated column; missing items inside a basket are ignored. Duplicate counts and item order are discarded.

🏞️ Front

The Nominal, Code, Ordered, Cyclic, Logical, and Basket tabs show eligible variables and proposed outputs, whether or not their encoding is enabled.

Nominal and Code tables report cardinality—the number of observed nonmissing levels—and the levels themselves. Nominal previews identify reference and pooled levels; Code previews identify the Target, method, and fold count. Ordered previews show the declared order. Cyclic previews show Period, Period units, Origin, and Cycle order. Logical previews show True, False, and missing counts. Basket previews list distinct items, output names, and empty and missing basket counts.

Messages explain missing prerequisites or unavailable variables. An unavailable panel does not prevent other selected encodings from being applied.

🔄 Flip side

Encoding audit describes only the enabled encodings, in pipeline order. Each row reports the source variable, encoding method, generated names, output count, whether the original remains, and explanatory notes. Selected variables that produce no columns remain visible with their reason; unavailable selections are also reported.

The summary gives predictor counts before and after this card, originals removed, and pipeline steps added by this card. Counts describe the current outgoing preview. Learned categories and output counts can differ between training folds.

🛠️ Controls and actions

The footer provides Encode nominal predictors, Encode Code predictors, Encode Ordered predictors, Encode Cyclic predictors, Encode Logical predictors, and Encode Basket predictors. Check any combination independently of the visible tab. There is no separate commit button.

Enabled transformations run in that order. Changing settings recalculates them; unchecking an option removes that encoding from this card’s output. With none selected, incoming data passes through unchanged.

Remove original variables applies across all panels and is enabled by default. Uncheck it to retain originals alongside numeric outputs. All-missing nominal variables, Ordered variables with fewer than two declared levels, and Basket variables with no observed items remain unchanged.

The card’s Tour Guide gives a concise description of each setting.

🔎 Interpretation and next steps

Check the audit before downstream modeling, especially when one-hot or polynomial encoding greatly increases the predictor count. Retaining originals may leave unsupported categorical inputs or duplicate representations for the next model.

Verify cyclic periods and level orders upstream. Ordinal ranks assume equally spaced positions; polynomial contrasts are orthogonal across equally weighted levels, not necessarily across an unbalanced sample. Encoding choices express assumptions about representation, not evidence of predictive usefulness.

⛔️ Limitations

  • Observation-importance weights are not used in counts, pooling, or target encoding.
  • Code encoding needs complete, finite Target outcomes and at least two training rows; classification needs at least two observations per class. Random cross-fitting does not protect against grouped or temporal dependence.
  • Except for Code values, which treat missingness as a category, missing inputs remain missing. Downstream imputation may still be necessary. Unseen-level behavior depends on the encoding and its settings.
  • Dense indicator expansion can be costly. Nominal, Ordered, and Basket encodings each limit generated features to 4096; polynomial degree is limited to 64.
  • Text and DateTime feature extraction are outside this card’s scope.

📌 Suggested workflow

  1. Assign Predictor roles and verify semantic types, orders, and periods upstream.
  2. Review each relevant panel; assign a Target if Code encoding is needed.
  3. Choose encoding methods and decide whether originals should remain.
  4. Enable the desired footer options and inspect Encoding audit.
  5. Evaluate the resulting pipeline within downstream training and validation.

🔗 Data flow

  • Input: Upstream data, semantic types, roles, and existing pipeline; Code encoding also uses a Target.
  • Output: Updated preview data and appended sklearn transformations. Generated columns are Predictors; retained columns preserve their roles. The pipeline’s original training input remains available.
  • Data journey: Each applied encoding family adds a Learning entry. Unselected, unavailable, or entirely unchanged families add no step.
