Variable data-type modification

A Pythagoras card

Nick Ward

🧭 Introduction

Variables can have the wrong data type due their form of storage. For example, CSV files do not distinguish between Text and Nominal, or between Text and Date. Sometimes, missing value place-holders (e.g. “missing”) can turn a column of numbers into a column of numbers-and-text. In this situation the data-type drops to the lowest common denominator which is “Text”.

Likert data consists of ordered responses—such as “strongly agree”, “neutral”, or “strongly disagree” — used in surveys to measure people’s opinions, attitudes, or feelings. It is not uncommon for such raw data sets to assign the wrong data-type to Likert variables. These variables need to be promoted to Ordinal. By default, order is simply alphabetical so they need to assigned an explicit ordering as well.

It is not uncommon for raw data sets to assign the wrong type to Cyclic variables such as days-of-the-week, months-of-the-year, seasons, and hours-of-the-day. These variables need to be promoted to Cyclic and have their explicit order given.

This dialogue allows the modification of variables. Variables can be renamed and have their data types changed. The “Alternatives values” settings controls the flexibility afforded to the data-type changes.

Changes are made by choosing a data variable from the rows of the table. The changes must be manually entered into the fields at the foot of the card. If the field shakes, the entry is not currently valid. For example, if the new variable’s name is already in use.

Nothing is actioned until pressing the “Commit” button at which point the modified dataset is propagated downstream. This button bounces when it is ready and able to be used. Mistakes can be reversed, in bulk, by pressing the “reset” button.

Strings can be flexibly converted to dates even if the date-format is not known. A list for possible formats will be attempted until a near-perfect translation is achieved.

⚙️ Settings

Use the Tour Guide button to learn about the settings of this card.

Possible date formats

A comma delimited list of alternative date (and time) formats to try. Order is important since the first format that succeeds on at least 95% of data values is considered the correct format for that variable. If you know the date format should be American style, ensure this format is at the front.

Date components

  • %Y — four-digit year, such as 2026
  • %y — two-digit year, such as 26
  • %m — zero-padded month number: 01–12
  • %B — full month name, such as January
  • %b — abbreviated month name, such as Jan
  • %d — zero-padded day of the month: 01–31
  • %j — zero-padded day of the year: 001–366

Time components

  • %H — zero-padded hour using the 24-hour clock: 00–23
  • %I — zero-padded hour using the 12-hour clock: 01–12
  • %M — zero-padded minute: 00–59
  • %S — zero-padded second: 00–59
  • %f — microseconds: 000000–999999
  • %p — locale-specific AM or PM

Weekday components

  • %A — full weekday name, such as Thursday
  • %a — abbreviated weekday name, such as Thu
  • %w — weekday number, where Sunday is 0 and Saturday is 6
  • %u — ISO weekday number, where Monday is 1 and Sunday is 7
  • %W — week number with Monday as the first day
  • %U — week number with Sunday as the first day
  • %V — ISO 8601 week number

Time-zone components

  • %z — UTC offset, such as +1200
  • %Z — time-zone name, such as NZST

Literal characters

  • %% — a literal percent sign
  • /, -, :, spaces and commas are included literally
Alternative types

This setting defines how the data types choices are filtered based on the nature of the variable.

  • Sensible: the feasible choices based on values and cardinality e.g. allowing low cardinality Text to Nominal. “Sensible” is the safest to use. It employs heuristic rules (involving data-values, data-type and cardinality) to identify type translations that should work correctly.
  • Related: the type-related choices are offered e.g. allowing Integer to Decimal. “Related” only uses rules relating to data-type.
  • All: all possible choices are offered. e.g. allowing Decimal to Text. “All” is not guaranteed to work, since all rules are disabled.

##### Max obs. to examine

Limit the maximum number of observations to test for alternative data types

🎯 Goals

  1. Primary: To fix mis-typed variables such as numbers that are recorded as text e.g. “20.1”,“12.7”,“45.3”.
  2. Secondary: Make it easy to change variable names and modify the order of Ordinal and Cyclic variables.

All cards downstream of this card will receive any changes enacted by this card.
