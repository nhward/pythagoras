Data journey

A Pythagoras card

Nick Ward

🧭 Purpose

The Data journey card explains how the data reaching this point was prepared. It distinguishes immediately materialized cleaning from transformations that must be learned during model training. The card is diagnostic and describes the current reactive path, not every state previously explored.

🎯 Goals

  1. Primary: Make the current sequence of cleaning and learning operations visible.
  2. Secondary: Expose unexpected ordering, settings, row loss, variable loss, or inactive operations.
  3. Tertiary: Support review and reproducibility without claiming to be a complete executable audit trail.

🧠 How it works

A mutable card records an operation when it changes data or adds a trainable pipeline step. It may also record an inactive operation when its data-changing control is not enabled. Immutable diagnostic cards normally pass data through without adding a step.

Stage Meaning
Source The imported starting dataset.
Cleaning A materialized correction, addition, removal, or role change.
Learning An unfitted scikit-learn step whose parameters must be learned from training data.
Preview The current full-data result used for interactive downstream displays.

Learning cards maintain both an unfitted pipeline step and a fitted full-data preview. The preview is useful for exploration but is not leakage-safe model training. During formal validation, the pipeline must be fitted separately within each training partition or resampling fold.

🏞️ Front

The front presents numbered boxes joined in execution order. Read the first row from left to right, the next from right to left, and continue in alternating directions. Curved connectors show where the journey turns. The number of boxes in a row responds to the available card width, so full-screen mode usually requires fewer turns. The chart sits in a vertically scrollable region as the journey grows.

Gray identifies the source, green identifies cleaning, orange identifies learning, and blue identifies the current preview. Hover over a box for compact details. The number inside it corresponds to the Step column on the flip side.

🔄 Flip side

The flip side provides one row per visible box. It records the stage, whether the operation was attempted, card identity, operation, method, variables, parameters, input and output shapes, and row and variable changes. A zero shape change does not prove that values were unchanged: recoding, imputation, centering, and scaling can preserve dimensions.

The table is filterable and is the authoritative view for long parameter or variable descriptions.

🛠️ Controls and actions

This card has no data-changing action. Hide steps that were not enabled affects only which recorded rows appear in the chart and table. It does not remove enabled operations that happened to make no change.

⚙️ Settings

The card’s Tour Guide gives a concise description of each setting.

🔎 Interpretation and next steps

Check the sequence, affected variables, and shape changes against the intended workflow. An inactive step can reveal that a card was present but its action was never enabled. Large reductions deserve investigation in the originating card. An orange step in the wrong position can create leakage or apply transformations in an unintended order.

⛔️ Limitations

  • The journey depends on what cards record and cannot reconstruct direct, unrecorded data-frame mutation.
  • It is descriptive rather than a complete executable recipe or regulatory audit trail.
  • It does not yet represent branches, merged sources, separate train/test paths, or ensembles.
  • External preprocessing, user identity, timestamps, source checksums, and every dependency are not systematically recorded.
  • The current journey changes reactively when upstream cards, settings, or ordering change.

📌 Suggested workflow

  1. Confirm the source name and shape.
  2. Follow the alternating rows in step-number order.
  3. Investigate unexpected cleaning reductions or role changes.
  4. Confirm that learning steps occur in the intended sequence.
  5. Reveal inactive steps and check whether an expected operation was omitted.

🔗 Data flow

  • Input: The upstream data, role map, recorded cleaning history, and learning pipeline.
  • Output: The upstream object unchanged.
  • Data journey: The card displays the journey but does not add itself as a step.
