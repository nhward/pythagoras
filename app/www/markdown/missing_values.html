A Pythagoras card

🧩 Missing Values

The assessment and resolution of missing values is multifaceted.

Firstly, the true missing values must be identified. This involves identifying placeholders for missing values. For example, addresses that hold the value “unknown”. Conversely, it also involves assigning obvious values to certain missing values through domain knowledge and careful reasoning.

After this each predictor in a dataset needs to have its missing values assessed with respect to prevalence, cause, [association](#association], and the nature of any missing values. It is important to determine these as they drive how missingness in each predictor should be handled. These are explained in the section called Assessment.

Finally, the resolution of missing values encompasses the use of shadow variables, variable removal, observation removal, imputation and implicit missing value tolerance. Imputation can be manual or learned. A mixture of several methods may be optimal. These are explained in the section called Resolution.

📋 Assessment

When assessing missingness it is useful to ask the following question of the data:

Is the missingness due an artifact of data curation or intrinsic to the ongoing data-generating and data-collection processes?

In other words, will the missingness continue into the foreseeable future or will it cease because it was due to merely historic problems. If any missingness can be expected into the future, ensure the model can tolerate this in its “prediction” mode.

📊 Prevalence

The prevalence levels are:

  • Excessively missing - A predictor whose missing values exceed an acceptability threshold
  • Somewhat missing - A predictor whose missing values fall below an acceptability threshold
  • Not missing - A predictor without missing values

It is best to assess predictor prevalence after excessively missing observations are removed. Excessively missing variables are best removed except it can be shown that they are important predictive variables.

🔍 Cause

The possible causes of missingness are:

  • Random - A predictor’s missingness has no pattern with respect to the non-missing values of other predictors. This cause is also known as Missing-completely-at-random (MCAR)
  • Patterned - A predictor’s missingness has a statistically significant model that predicts much of the missing values using the (non-missing) values of other predictors. This cause is also known as Missing-at-random (MAR)
  • Explainable - A predictor’s missingness can be explained by the values that would have existed. By its nature, this is difficult to diagnose using the data. This cause is also known as Missing-not-at-random (MNAR)

🔗 Association

Variables often have similar causes of missingness that show as correlated missingness. The sharing of common causes or shared causes between predictors can be assessed through the use of Association rules, Jaccard Index, and the Upset Chart.

When association is present, this can lead to observations having either few or many missing values. The distribution of observation missingness may show a bimodal

🧬 Nature

In addition there is a nature of missingness to consider:

  • Informative - A predictor’s missingness may be predictive of the target.
  • Uninformative - A predictor’s missingness may not be predictive of the target.

✅ Resolution

The resolution of missing values is about ending up with a dataset that no longer has missing values. Doing so needs to proceed in a particular order.

📍 1 Placeholders for missing-values

Not all non-missing values are real. Sometimes, when a entry is compulsory, people will enter a placeholder value to indicate that they have no valid value to offer. For numeric values, -99 has historically suggested that the value is effectively missing. An address that is written as “unknown” again signifies missing data. All such candidate values need to be judged as to whether they are converted to missing values.

Issues:

  • It requires domain knowledge to reliably assign placeholders to missing values.

Example:
When a patient is given the name “Jane Doe”, the suggestion is that the name is not actually known. Combining the records of all the “Jane Does” would be a bad idea.

✍️ 2 Manual imputation

Manual imputation is the process of in-filling certain explainable missing values based upon logic and domain knowledge. This need not apply to all the missing values of a single variable. Sparse data is a classic example of the need to manually assign values to the missing values.

Sparse data is a dataset where most values are zero, empty, or missing. This happens when a large table has very few actual entries compared to its total size. Common examples include:

  • Movie ratings: Most users rate only a few films out of thousands available.
  • Word lists: Most documents use only a tiny fraction of all words in a dictionary.
  • Online shopping: Most buyers purchase only a few items from a huge store.

Issues:

  • Manual imputation needs to occur before any other resolution so that only unexplainable missing values get down-stream processing.
  • Ideally this is done programmatically and is carefully documented for repeatability.
  • Consider whether the programmed in-filling is able to be applied when predicting future observations (in production) which might also contain missing values.

Example:
Blood-test results can be missing because no diagnostic justification for the test has yet arisen. Were such tests undertaken unnecessarily they would usually yield results in the normal range (rather than in the extreme range). A possible manual imputation might involve substituting a typically “Normal” result for each missing test. Substituting a mean result (as learned imputation might) would be a poor choice.

🌘 3 Shadow variables

Shadow variables are additional binary variables manufactured to record which values are missing. When the missing values have an Informative nature, a shadow variable supplies this valuable information to the model-fitting even if the values are subsequently imputed.

Issues:

  • Shadow variable production needs to occur before any imputation.
  • When the missing values are Uninformative the additional shadow variables will be no use. A variable selection stage should attempt to remove unnecessary shadow variables.

Example:
The absence of clinical notes is often caused by periods of high workload and surgery emergencies. The target may also be affected by periods of high workload and surgery emergencies. This absence of clinical notes may be informative and a shadow variable should be generated to capture this information.

✂️ 4 Variable removal

When a variable has a large percentage of missing values, a threshold may be reached where it becomes challenging to perform learned imputation, and the alternative data loss due Observation removal becomes excessive.

Issues:

  • That threshold point changes depending upon the “importance” of the variable to the target. Best practice would be to vary this as a hyper-parameter during model tuning.
  • Variable removal must precede Observation removal to maximize the number of training observations when these resolutions are used in conjunction.

Example:
Polio protocols have remained absent for decades. The data is more missing than present. This variable deserves to be removed until further notice.

🗑️ 5 Observation removal

Observation removal involves the deletion of observations with (relevant) missing values. This leaves a reduced number of entirely complete observations with which to fit the model. This resolution style is also known as Partial deletion. A more sophisticated variation of this idea can be employed to only remove observations whose incompleteness exceeds a certain threshold.

Issues:

  • What constitutes excessive missingness is poorly defined. Best practice would be to vary this threshold as a hyper-parameter during model tuning.
  • Observation removal risks introducing data bias if there is some pattern to the missing values. Only truly random missingness is guaranteed to avoid data bias.
  • What constitutes relevant predictors may not yet be clear. If a model ends up using only 10 out of 40 predictors, then these 10 are the relevant ones. Best practice would be to iterate through a range of variable importances to discover what might be relevant to Observation removal.
  • The number of observations decreases leading to weaker model fitting. This makes Observation removal something to increasingly avoid with smaller sample sizes.

Example:
Instrument failures prevent the recording of routine blood pressure readings. Records involving missed BP readings can be safely ignored as they are believed to occur randomly. No data bias can be associated with a random process.

🧠 6 Learned imputation

Learned imputation is a process of predicting the missing values. It enables observations to remain in the training sample despite being incomplete. This is also known as Statistical imputation.

Issues:

  • It is wrong to think that Learned imputation will necessarily provide accurate predictions. This can be explored by generating CV metrics for such models.
  • If the observations are truly independent and predictors are truly independent, then Learned imputation will necessarily be on a par with a constant value estimation.
  • Some complex imputation techniques are slow to train.
  • Learned imputation has a role to play even in the absence of missing values. The reason for generating a missing value predictor may lie with future in complete observations (in production)
  • Learned imputation need good predictors. Feature extraction may need to be performed before a strong imputation model can be built.

Example:
The absence of clinical notes is often caused by periods of high workload and surgery emergencies. This is not random: it happens frequently on Friday and Saturday nights. The missing notes might best be estimated by a note typical of the day-of-week and time. Day-of-week needs to be extracted from the observation date first in order to facilitate the imputation training.

👻 7 Implicit missing value tolerance

Many models are capable of tolerating missing values by applying a strategy that either removes observations or implicitly imputes according to their proprietary algorithm. Many “Tree” models employ a form of Learned imputation. Many “Linear” models employ a form of Observation removal.

Issues:

  • If you are trialing many model types, some of which have no Implicit missing value tolerance (e.g. SVM), you will need to explicitly employ Learned imputation (or Observation removal) for all models, in order to provide a fair trial of all models.
  • Whether a particular model type has Implicit missing value tolerance is often unclear. Intolerant ones may or may not prove exceptions that explain the intolerance clearly.
  • Though more convenient, Implicit missing value tolerance should be be assumed to lead to a better result than explicit management of missing values.

Example:
XGBoost is a good general modeling method that copes well with missing data. Since it is the sole method being considered in the study, I can bypass some missing-value issues. I still need to consider a) missing-value placeholders, b) Manual imputation of explainable missing-values, c) excessive variable missingness, d) excessive observation missingness, and e) Shadow variables for informative missingness.
